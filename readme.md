# SCALE-FL (Secure Aggregation + SGX + Federated Learning)

SCALE-FL is an end-to-end federated learning (FL) system that combines:

- **Secure aggregation** using the **TERSE** protocol (used as the cryptographic primitive)
- An optional **trusted execution** deployment for the decryptor (e.g., **SGX/Gramine**)
- An **FL demo** (Flower-based) showing how encrypted client updates are aggregated and then decrypted inside the trusted component

This README focuses on **how to build and run SCALE-FL**, with an emphasis on the **Python library** (`terse_py`) that the FL pipeline uses.

---

## Repository highlights

- `python/`
  - `terse_python.cpp`: Python bindings (via `pybind11`)
  - `test_python_bindings.py`: quick sanity test for the Python API
- `include/` and `src/`
  - C++ implementation and executables used for setup and (optionally) trusted decryption
- `terse-fl/`
  - Flower demo app (client + server) integrating encryption/aggregation/decryption into FL
- `sgx/`
  - Gramine/SGX manifests and launchers for running trusted components in an enclave (optional)
- `data/`
  - Working directory where setup artifacts and per-round inputs/outputs are written/read

## Build (Python-first)

### Prerequisites
- Python 3
- Python packages:
  - `numpy`
  - `pybind11`
- C++17 toolchain
- OpenFHE + OpenSSL (for the underlying crypto implementation)
- Optional (for enclave runs):
  - Gramine + SGX runtime/tooling on an SGX-capable machine

### Build the Python module
From the repo root:

```bash
make python
```

This produces `python/terse_py*.so`.

### (Recommended) Also build native tools
The Python workflow typically depends on setup artifacts generated by C++ tools:

```bash
make core
```

## SCALE-FL “data directory” contract

Most scripts/components assume:
- you run them from the **repo root**
- all artifacts are read/written under `./data/`

Common files include:
- `data/params.bin`
- `data/server_key.bin`
- `data/client_precompute_<i>.bin`
- `data/encrypted_aggregate_<ts>.bin`
- `data/decrypted_<ts>.bin`

## Generate setup artifacts (needed for SCALE-FL runs)

SCALE-FL uses TERSE under the hood, which requires generating parameters/keys and client precomputation files.

### 1) Trusted setup (generates params, keys, schedule metadata)
```bash
./setup_trusted <n_clients> <n_rounds> <n_chunks> <vector_dim> <fraction_fit> [schedule_seed]
```

### 2) Client precomputation (per-client files used by encryption)
```bash
./setup_clients <n_clients> <n_rounds> <n_chunks> <vector_dim>
```

After this, Python code can encrypt/aggregate using the generated `./data/*` artifacts.

## Python library (`terse_py`) usage (core pieces)

Import:

```python
import terse_py
```

### Client: encrypt an update vector
```python
import numpy as np
import terse_py

c = terse_py.TERSEClient("data/params.bin", client_idx=0)

x = np.zeros(1024, dtype=np.uint32)
ct = c.encrypt_vector(x, timestamp=0)  # returns uint64 numpy array
```

### Server: aggregate ciphertexts (untrusted)
```python
import terse_py

s = terse_py.TERSEServer("data/params.bin")
agg = s.aggregate_ciphertexts([ct1, ct2, ct3], timestamp=0)
```

### Trusted: decrypt the aggregate sum
```python
import terse_py

t = terse_py.TERSETrusted("data/params.bin", "data/server_key.bin")
pt_sum = t.decrypt_aggregate(timestamp=0, vector_dim=1024)  # uint32 numpy array
```

## Run the SCALE-FL Flower demo (recommended end-to-end path)

The Flower demo lives under:

- `terse-fl/pytorchexample/client_app.py`
- `terse-fl/pytorchexample/server_app.py`

High-level flow:
- clients train locally, quantize, and encrypt updates using `terse_py`
- server aggregates encrypted updates
- a trusted component decrypts the aggregate (optionally in SGX)
- server applies the decrypted aggregate to update the global model

How to run it depends on how the demo is packaged in your repo (some setups use Flower CLI entrypoints; others run the server/client apps directly). If you tell me how you currently launch it (command(s) you use today), I can write the exact run commands in this README.

## Optional: run the trusted decryptor in SGX/Gramine

If you want the trusted decrypt step to run inside an enclave:

```bash
make sgx
```

Typical patterns include running setup and/or the trusted decrypt service under SGX, for example:

```bash
gramine-sgx sgx/setup_trusted <n_clients> <n_rounds> <n_chunks> <vector_dim> <fraction_fit> [schedule_seed]
gramine-sgx sgx/trusted_round
```

The Flower demo commonly uses a long-running trusted decrypt service (`trusted_round`) and communicates with it during training rounds.
